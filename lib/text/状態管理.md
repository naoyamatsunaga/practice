# 状態管理の実装

## 概要

このアプリでは、**Riverpod**を使用して状態管理を行っています。Riverpodは、Flutterアプリケーションで状態を効率的に管理するための強力なライブラリです。

## 実装した機能

### ポイント合計値の表示

Taskの合計値をHome画面の上部に表示し、ポイントを追加・編集・削除するとリアルタイムで合計値が更新されるように実装しました。

## 状態管理の仕組み

### 1. Riverpodとは

Riverpodは、Flutterの状態管理ライブラリの一つです。以下の特徴があります：

- **型安全**: コンパイル時にエラーを検出できる
- **テストしやすい**: Providerを簡単にモックできる
- **パフォーマンス**: 必要な部分だけを再構築するため、効率的
- **依存関係の管理**: Provider間の依存関係を自動的に管理

### 2. Providerの種類

このアプリでは、以下の3種類のProviderを使用しています：

#### `databaseProvider` (Provider)
**ファイル**: `lib/models/data/database.dart`

```dart
final databaseProvider = Provider<AppDatabase>((ref) {
  throw UnimplementedError('databaseProviderはmain.dartで上書きする必要があります');
});
```

- **役割**: データベースインスタンスを提供
- **特徴**: アプリ全体で同じデータベースインスタンスを使用するために使用
- **上書き**: `main.dart`で実際のデータベースインスタンスで上書き
- **依存関係**: なし（最下層のProvider）

#### `homeTaskListStreamProvider` (StreamProvider)
**ファイル**: `lib/view_models/home_view_model.dart`

- **役割**: 現在期間内のタスク一覧をリアルタイムで監視
- **特徴**: `taskRepositoryProvider` 経由で DB を購読し、リセット時刻でフィルタ
- **依存関係**: `taskRepositoryProvider`, `resetTimeProvider`

#### `homeTotalPointsProvider` (Provider)
**ファイル**: `lib/view_models/home_view_model.dart`

- **役割**: 完了済みタスクのポイント合計を計算
- **特徴**: `homeTaskListStreamProvider` に依存し、リスト更新で再計算
- **依存関係**: `homeTaskListStreamProvider`

### 3. データの流れとファイル構成

```
AppDatabase
    ↓ databaseProvider（lib/models/data/database.dart）
    ↓
TaskRepository
    ↓ taskRepositoryProvider
    ↓
homeTaskListStreamProvider（フィルタ付き）
    ↓
homeTotalPointsProvider
    ↓
HomePage（lib/views/pages/home_page.dart）
```

### 4. ファイル間の依存関係

- `home_view_model.dart`: `task_repository.dart`, `settings_view_model.dart`, `core/utils/reset_time.dart`
- `home_page.dart`: `home_view_model.dart` を import して `ref.watch` / `ref.read`
- `main.dart`: `database.dart` の `databaseProvider` を override

### 5. UIでの使用方法

#### ConsumerWidgetの使用

`HomePage` は `ConsumerWidget` として実装しています：

```dart
import 'package:practice/view_models/home_view_model.dart';

class HomePage extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final totalPoints = ref.watch(homeTotalPointsProvider);
    final taskPointsAsync = ref.watch(homeTaskListStreamProvider);
    // ...
  }
}
```

#### ref.watch()の役割

- **監視**: Providerの値を監視し、値が変更されると自動的に再構築
- **依存関係の構築**: Provider間の依存関係を自動的に構築

### 6. リアルタイム更新の仕組み

1. **データベースの変更**: ポイントを追加・編集・削除すると、データベースが更新される
2. **Streamの通知**: `watchTasks()`が新しいデータを通知
3. **StreamProviderの更新**: `homeTaskListStreamProvider` が新しいリストを受け取る
4. **依存Providerの再計算**: `homeTotalPointsProvider` が自動的に再計算される
5. **UIの更新**: `ref.watch()`で監視しているWidgetが自動的に再構築される

### 7. main.dartでの設定

```dart
import 'package:practice/models/data/database.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final database = AppDatabase();
  runApp(
    ProviderScope(
      overrides: [
        databaseProvider.overrideWithValue(database),
      ],
      child: const MyApp(),
    ),
  );
}
```

- **ProviderScope**: アプリ全体で Riverpod を使用できるようにする
- **overrides**: `databaseProvider` を実インスタンスで上書きする
- **インポート**: `package:practice/models/data/database.dart`

## メリット

1. **自動更新**: データが変更されると、関連するUIが自動的に更新される
2. **型安全**: コンパイル時にエラーを検出できる
3. **テストしやすい**: Providerを簡単にモックできる
4. **パフォーマンス**: 必要な部分だけを再構築するため、効率的
5. **保守性**: 画面ごとに ViewModel ファイルへ Provider をまとめて追いやすい
6. **可読性**: `MVVM構成.md` / `ファイル構成.md` と合わせて参照できる

## 今後の拡張

この状態管理の仕組みを活用して、以下のような機能を追加できます：

- ソート機能（ポイント順、日付順など）
- 統計情報の表示（平均値、最大値、最小値など）
- カテゴリ別の集計

## まとめ

Riverpodを使用することで、状態管理がシンプルで保守しやすくなりました。Provider間の依存関係が自動的に管理されるため、データの流れが明確で、バグが発生しにくいコードになっています。
